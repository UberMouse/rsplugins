## The API reference (`api/`)

`docs/api/` is a gitignored symlink, made by the dev shell's `shellHook`, to
[FriendlyDevelopment/runescape-api-stubs](https://github.com/FriendlyDevelopment/runescape-api-stubs):
community LuaLS stubs generated from the developer site's HTML. It is pinned as the `api-stubs`
flake input (see `flake.lock`) rather than vendored, because that repo has no licence. Bump it
with `nix flake update api-stubs`.

- `generated/<section>/<page>.lua` mirrors the site's pages: `core/`, `game/` (with `config/`,
  `entity/`, `list/`), `math/`, `ui/` (with the component folders) and `audio.lua`. Find a member
  with e.g. `grep -rn 'function Player\.' docs/api/generated/`, or an event payload in
  `generated/core/events.lua`.
- `types.lua` holds hand-written aliases and the `id`/`config`/`var` ID types.
- `consts/` has every named ID (`id.Obj.*`, `var.VarPlayer.*`...), about 50 MB. It is not loaded
  by `.luarc.json` (it makes LuaLS crawl), but you can grep it for names.
- The same stubs drive the LuaLS step of `scripts/check-lua.sh`, so an API call that does not
  match them fails the gate.

They're generated from the official HTML and partly hand-edited, so they inherit the docs' gaps
and can lag a site update. Check the official page when details matter. If you need the raw site,
**`https://developer.runescape.com/rs/search.json`** is its full-text index: ~1300
`{location, level, title, text(HTML), path}` entries, one per heading section. Only scrape the
**public** site (see the AI policy in [guidelines.md](guidelines.md)).
